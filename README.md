# fetch-market-data

一个给 **Kimi（Kimi Work / Kimi Code agent）** 用的技能包：在 Kimi 调用付费数据源批量下载行情/宏观数据**之前**，预注入踩坑经验与操作规范，让 agent 开局就自带"老司机路况知识"，不用每次重新试错。

## 解决什么问题

Kimi 通过插件调用同花顺 iFinD、万得 Wind、FRED、Eurostat、ECB 等数据源时，插件自带的 skill 只写"API 有哪些参数"（地图），不写"哪些路在修、哪里会限流"（路况）。真实批量下载时 agent 会反复踩同一批坑：

| 坑 | 后果 |
|---|---|
| iFinD 主力连续代码是 `RB8888.SHF` 不是 Wind 习惯的 `RB888.SHF` | 批量调用全部返回 EMPTY，白烧额度 |
| iFinD 指数时间列是整数 `yyyymmdd`，直接 `pd.to_datetime` 得到 1970 年 | 数据落盘即废，且不易察觉 |
| Wind CLI 输出是 Python-dict-repr 不是 JSON；`@file` 参数语法不支持 | 解析崩溃，子进程 GBK 解码中文即报错 |
| Wind 自然语言匹配会选错指标（"城镇调查失业率"→"IMF预测：失业率"） | 拉到错误数据，污染研究结论 |
| Wind 部分指标无权限（中债 10Y 收益率）、部分日度序列宽区间必失败 | 死循环重试，烧光额度 |
| FRED 上 OECD 序列各有停更时间（日本 CPI 止于 2022-04 等） | 拿到滞后数据不自知 |
| Eurostat `top≤1000`、time 过滤一次最多 20 个值、key 必须 8 段 | 截断/拒绝，隐形缺口 |

这些知识只存在于"上一次成功的会话"里，不固化下来，下一个会话从零开始。

## 插入逻辑：装在 Kimi 批量下载数据的哪个环节

```
用户：把这 50 个品种的数据拉下来
        │
 ① 技能索引扫描（仅 name+description，~100 词常驻）
        │
 ② fetch-market-data 命中（批量下载/建数据池/调用失败 等触发词）
        │
 ③ 加载 SKILL.md：源路由表 + 通用工作流
    （探针先行 → 分段 → 有界重试 → 合并去重 → 校验 → 记录数据池）
        │
 ④ 按路由只读对应 references/<source>.md（用 Wind 不读 iFinD 的坑）
        │
 ⑤ 指引加载对应插件自己的 skill 拿权威 API 契约
        │
 ⑥ scripts/*.py 确定性执行（分段/重试/解析已编码，不再消耗试错额度）
```

定位：**编排经验层**。不替代插件 skill（工具契约层，唯一权威），不重复其参数文档，只补充契约之外的实战行为。

## 实测效果

在 2026-11-01 的真实任务中（54 个期货品种 × 11 年日线 + 74 条五国宏观序列）：

- 全部数据成功落盘，零缺失零重复
- 过程中 **8 次失败调用**靠 references 中的坑点知识直接恢复（错误码 → 对策 一一对应），无一次靠反复重试蒙对
- 校验脚本额外抓出真实数据问题：动力煤 2021-10 后长期停牌（3700 个 NaN）
- 补缺口时按路由表直接确认"中国 10Y 国债收益率无可用源"，没有浪费调用额度去试错

## 自迭代闭环

技能不是写完即冻结的文档，而是持续进化的经验库：

```
执行 → 遇到新坑 → 把坑点+对策回灌 references/ → 后续所有实例开局自带新知识
```

本仓库已实战演示一次：测试 ECB 新源时发现"日度序列 start 必须传完整日期""top=1000 会静默截断 4 年分段"两个新坑，当轮即回灌；校验脚本也在复验中进化为"NaN 告警、重复才失败"。

## 按需加载设计（references 路由）

不把所有坑点塞进一个文件，避免多源任务时交叉污染上下文：

```
fetch-market-data/
├── SKILL.md                 # 路由表 + 通用工作流（<500行，永远加载）
├── references/
│   ├── ifind.md             # 仅 iFinD 任务时加载
│   ├── wind.md             # 仅 Wind 任务时加载
│   └── fred-eurostat.md    # 仅 FRED/Eurostat/ECB 任务时加载
└── scripts/
    ├── fetch_ifind.py       # 探针/单品种/批量 三模式（实战验证 54 品种）
    ├── fetch_wind_edb.py    # 解析落盘 CSV 路径 + 自动定位 node（16 指标验证）
    └── validate_pool.py     # 全库校验（NaN 告警/dup 失败，--strict 可选）
```

代价模型：单源任务只多付一份 reference 的上下文；多源任务才依次追加。

## 安装

Kimi Work / Kimi Code 的托管技能目录：

```
<daimon-share>/daimon/skills/fetch-market-data/
```

放入后重启会话即出现在技能索引中，命中"批量下载数据 / 建数据池 / 数据源调用失败"等场景自动触发。
